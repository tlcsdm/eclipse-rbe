Preferences

Open the ResourceBundle Editor preferences via Window > Preferences > ResourceBundle Editor. There are three preference pages:

General

PreferenceDescription
Convert \uXXXX to unicode on read When enabled, escaped Unicode sequences in .properties files are automatically decoded to their Unicode characters when the file is loaded.
Convert unicode to \uXXXX on write When enabled, non-ASCII characters are automatically escaped as \uXXXX sequences when the file is saved.
Use uppercase hex letters When writing Unicode escapes, use \uXXXX (upper-case) instead of \uxxxx (lower-case).
Tab key inserts a tab character When editing a value in the form view, pressing Tab inserts a literal tab character instead of moving focus to the next field.
Displayed locales Comma-separated list of locale patterns (supports * and ? wildcards) that restricts which locales are shown in the editor. Defaults to * (show all).
Don't display the key tree Hides the key tree panel in the form view for a more compact layout.
Minimum editor height Sets the minimum height (in pixels) for individual value editors in the form view.
Sort keys alphabetically When saving, keys are written in alphabetical order.
Keep properties with empty values When enabled, keys with empty values are retained in the file on save; when disabled they are removed.
Show "Generated By…" comment Prepends a comment header with the ResourceBundle Editor URL to every saved file.
Support loading resources from fragments When enabled, the editor also discovers .properties files from Eclipse fragment projects.
Load only fragment resources Limits discovery to fragment resources only, ignoring the host plug-in.
Support Eclipse "nl" structure Enables support for the nl/ directory structure used for Eclipse plug-in internationalization.
Key tree is hierarchical by default New editors open with the key tree in hierarchical mode.
Key tree is expanded by default New editors open with the key tree fully expanded.

Formatting

PreferenceDescription
Align equal signs Pads key names with spaces so that all = signs appear on the same column.
At least one space around equal signs Ensures there is at least one space on each side of the = separator.
Group keys Groups keys by their common prefix (determined by the separator character) with optional blank lines between groups.
Key group separator Character used to determine key groups (default: .).
How many level deep Number of levels of the key hierarchy to use when grouping.
Align equal signs within groups When grouping is active, aligns = signs independently within each group.
How many lines between groups Number of blank lines inserted between key groups.
Wrap long lines Breaks values that exceed the configured character limit with a \ continuation escape.
Wrap lines after N characters The column at which line-wrapping is triggered.
Wrap indentation spaces Number of spaces added at the start of wrapped continuation lines.
Align wrapped lines with equal signs Indents continuation lines to align with the value column.
Wrap lines after escaped new line characters When a value contains a literal \n escape, inserts an actual line break at that position for readability.
Force new line escape style Forces the use of a specific line-ending style (CR, LF, or CRLF) in saved files.

Performance

The following features may have a significant performance impact on large bundles. Enable them selectively.

PreferenceDescription
Report keys with missing values Shows a warning icon on keys that are missing a translation in at least one locale.
Report keys with duplicate values Highlights keys that share identical values with another key in the same locale.
Report keys with similar values Highlights keys whose values are similar (but not identical) to another key.
Use Levenshtein distance Uses the Levenshtein edit-distance algorithm for similarity detection.
Use identical word count Uses the proportion of common words for similarity detection.
Precision level Threshold (0–1) for reporting similar values. Higher values mean less sensitive.
